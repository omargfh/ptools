# AGENTS.md

Single source of truth for agents in this repo. `CLAUDE.md` symlinks here.

## Core values

1. **Small and atomic.** Commits, PRs, plans: smallest self-contained slice, one clear goal, tested. See `agent_docs/commits.md`.
2. **Evidence over assertion.** Every claim traces to `path:line` or a verified command. Unverifiable → downgrade or drop.
3. **Signal over noise.** Report deviations, not narration. "No findings" is a valid result. No praise, hedging, or filler.
4. **Static first.** Read before running. Execute only to confirm or kill a specific hypothesis — never to explore, never with network access or destructive side effects.
5. **Approval gates.** Analysis produces a report; changes land only after explicit approval. Mid-fix discoveries go back into the report, not silently into the diff.
6. **Abstractions pay rent.** No pattern without the concrete cost it removes; extract at the third occurrence. Correctness beats speed — when they conflict, say so.
7. **CI is enforcement.** Weakening CI, skipping tests, or breaking lockfile parity is a defect even when green.
8. **Token discipline.** Small context footprints, pre-handled static content, capped doc length.
9. **Docs don't lie.** A doc (or a name) claiming behavior or enforcement that doesn't exist gets fixed or flagged — never worked around.

## Process

- `agent_docs/commits.md` — read before any commit.
- `agent_docs/pr-review.md` — the PR review process; the deliverable is a report.
- `.ongoing/README.md` — where future work is planned, PR-sliced.

## Repo

`ptools` is a personal Python CLI toolbox (`pyproject.toml:1-3`): a single `ptools` entry point that lazily dispatches ~20 independent subcommands — filesystem (`touch`, `fs`, `watch`), process inspection (`proc`), LLM chat (`llm`), secrets/encryption (`vault`, `secrets`), and more — each with its own tests and Sphinx-generated docs.

### Layout

| Path | Responsibility |
| --- | --- |
| `src/ptools/*.py` | One file per top-level CLI subcommand (`touch.py`, `flow.py`, `proc.py`, …), registered in `main.py`'s `COMMANDS` dict |
| `src/ptools/lib/` | Reusable engines behind the heavier commands: `flow/` (expression runner), `proc/` (process explorer + Textual TUI), `llm/` (chat client, REPL, history), `shellc/` (shell-script compiler), `fs/` (file-tree TUI, watchers), `tui/` (shared select/table/chart widgets) |
| `src/ptools/utils/` | Cross-cutting helpers: config storage (`config.py`), encryption (`encrypt.py`), the `require` decorators that gate optional deps (`require.py`), serialization (`serial.py`) |
| `src/ptools/formats/` | Serializer/deserializer backends (`json.py`, `yaml.py`) registered with `utils/serial.py`'s factory |
| `src/ptools/models/` | Pydantic default-config schemas |
| `src/ptools/starters/` | Packaged starter config data (`touch.yaml`, `literals.json`), loaded via `importlib.resources` to seed a user's config on first run (`utils/config.py:30-43`) |
| `tests/` | pytest suite mirroring `src/ptools` 1:1 (`tests/lib/`, `tests/utils/`) |
| `scripts/` | One-off dev scripts; currently just `generate_requirements.py` |
| `docs/` | Sphinx source; `cli.rst` renders the live Click command tree via `sphinx_click` (`docs/conf.py:34`) |

### Commands

- **Run the CLI**: `.venv/bin/ptools --help` (verified). `python3 -m ptools.main --help` does **not** work — see Gotchas.
- **Test**: `.venv/bin/python3 -m pytest` (verified — 372 tests collected; `pyproject.toml` sets `pythonpath = ["src"]` so no install is required).
- **Lint / typecheck**: unverified — `pyproject.toml` configures `[tool.pyright]`, but pyright is not installed in `.venv` and no lint tool (ruff/flake8/black) is configured in the repo.
- **Docs build**: `.venv/bin/python3 -m sphinx -M html docs docs/_build` (verified via `sphinx-build --help`). Do not use `make -C docs html` — see Gotchas.
- **Requirements**: `.venv/bin/python3 scripts/generate_requirements.py` prints a full requirements list to stdout; its output currently drifts from the committed `full_requirements.txt` — see Gotchas.

### Gotchas

- `.venv/bin/python3` has no `pip` module (`No module named pip`) — packages are managed externally; don't try to `pip install` into this venv.
- `python3 -m ptools.main --help` silently exits 0 with no output: `main.py` has no `if __name__ == "__main__"` guard. Use `.venv/bin/ptools` or `python -c "from ptools.main import cli; cli()"`.
- `make -C docs html` is a silent no-op (`make: Nothing to be done for 'html'`): `html` is listed in `docs/Makefile`'s `.PHONY` with no recipe, which pre-empts the catch-all `%: Makefile` rule. Use `python3 -m sphinx -M html docs docs/_build` instead.
- `full_requirements.txt` claims to be regenerated by `scripts/generate_requirements.py`, but running the script now produces a different file (duplicate `darwin` binary lines, different header punctuation, a different `tabulate` floor). Hand-edit `full_requirements.txt` rather than regenerating until the generator is fixed (`.ongoing/requirements-generator-drift`).
- No CI workflow runs the test suite — `.github/workflows/docs.yml` only builds/deploys Sphinx docs (`.ongoing/ci-test-workflow`).
- Adding a subcommand means registering it in `src/ptools/main.py`'s `COMMANDS` dict (`"module:attribute"` import path + `short_help`); `LazyGroup` won't discover it otherwise.
- Command docstrings are the docs: `docs/cli.rst` renders the live Click tree via `sphinx_click`, so help-text edits are doc edits.
- Reuse `ptools.lib.tui.select.SelectApp` / `ask_text` for any new interactive prompt instead of building a new picker or using raw `prompt_toolkit` widgets (e.g. `RadioList`); keep long option lists passed through `max_visible` so they stay scrollable.
- Don't name a custom `prompt_toolkit` style class `selected` in `tui/select.py` — it collides with a class prompt_toolkit's default UI style already defines as `reverse`.
- Textual TUIs (`FileTreeApp`, `ProcApp`) can be smoke-tested headlessly with `app.run_test()` + pilot key presses instead of a real terminal.
